# 학술제 녹화 가이드

학술제(예선, 본선 2026-11-10)에서는 재생 화면을 발표장에서 띄우지 않고 녹화 영상을 쓴다(2026-10-18 결정). 그래서 노트북 환경 준비와 오프라인 리허설은 하지 않는다. 슬라이드와 포스터에 넣을 정지 화면도 같은 화면에서 찍는다.

서버에는 모니터가 없다. 화면은 서버에서 띄우고, 노트북 브라우저로 열어서, 노트북의 화면 녹화로 찍는다.

## 1. 구간 내보내기 (서버)

화면은 미리 내보낸 구간 파일(`segments/`, git 밖)만 읽는다. 구간은 거래소 시각(UTC)으로 자르고 2시간까지다. 15분 구간이 0.36MB 이고 내보내는 데 30초쯤 걸린다.

| 장면 | 파일 | 구간 (UTC) | 상태 |
|---|---|---|---|
| 갭 | `segments/gap-0732.npz` | 2026-10-07 07:25 ~ 07:40 | 있음 |
| 급락 | `segments/drop-0156.npz` | 2026-10-07 01:50 ~ 02:05 | 아래 명령으로 만든다 |

```bash
nice -n 19 uv run python scripts/export_replay_segment.py 2026-10-07T01:50:00 2026-10-07T02:05:00 segments/drop-0156.npz
```

갭 구간을 다시 만들어야 하면 이렇게 만든다.

```bash
nice -n 19 uv run python scripts/export_replay_segment.py 2026-10-07T07:25:00 2026-10-07T07:40:00 segments/gap-0732.npz
```

## 2. 화면 띄우기 (서버)

```bash
nice -n 19 uv run --group screen streamlit run tickfold/screen/app.py
```

화면은 127.0.0.1:8501 로만 받는다. 수집기와 CPU 를 나눠 쓰므로 다 찍으면 `Ctrl + C` 로 끈다.

## 3. 노트북에서 열기

`<서버>` 는 평소 SSH 로 붙는 주소다.

```bash
ssh -L 8501:127.0.0.1:8501 <서버>
```

터널을 연 채로 노트북 브라우저에서 `http://localhost:8501` 을 연다. 15분 구간은 처음 고를 때 12MB 쯤 받아서 몇 초 걸린다. 같은 구간을 다시 고르면 브라우저 캐시에서 바로 뜬다.

슬라이드가 16:9 라서 브라우저를 전체 화면(크롬은 `F11`)으로 두고 찍으면 그대로 붙일 수 있다.

## 4. 녹화

| 노트북 | 방법 |
|---|---|
| macOS | `Cmd + Shift + 5` → "선택 부분 기록" 으로 브라우저 창만 고른다 |
| Windows 11 | 캡처 도구(`Win + Shift + S`)의 녹화, 또는 Xbox Game Bar(`Win + Alt + R`) |

- 브라우저 창만 찍는다. 터미널에는 서버 이름과 경로가 보여서 영상에 넣지 않는다.
- 해상도는 1080p 로 둔다. 재생은 초당 10번 그리므로 녹화는 30fps 면 충분하다.

## 5. 장면

### 장면 1: 갭 (40초 안팎)

거래소 연결이 밀리다가 끊긴 24.9초를 화면이 어떻게 보여 주는지 찍는다.

1. 구간 고르기에서 `gap-0732` 를 고른다.
2. 맨 위 숫자 띠를 확인한다. 프레임 8,751, 갭 1개, 24.9초, 놓친 변경 16,777, 가장 긴 전달 지연 22.4초다.
3. 갭 바로가기 단추를 누른다. 갭 직전 프레임 3초 앞에 멈춘 채로 선다.
4. 녹화를 시작하고 1배속으로 재생한다.
5. 보이는 것:
   - 호가창이 3초 움직이다가 07:32:00.014 에서 멈춘다.
   - "갭 24.9초 가운데 n초째" 안내가 뜬다.
   - mid 그림의 세로선만 회색 띠 안을 지나간다.
   - 07:32:24.914 부터 다시 움직인다.

말할 거리: 수집기는 이 구간을 갭으로 기록하고 다시 연결된 뒤 1초 안에 재동기화했다. 화면은 받지 못한 24.9초의 호가를 지어내지 않고 멈춘 채로 보여 준다.

### 장면 2: 급락 (40초 안팎)

2026-10-07 에서 가장 큰 5분 하락이다. 01:56:19 ~ 02:01:19 UTC 에 mid 가 85,066.61 에서 83,615.01 로 1.706% 빠졌다.

1. 구간 고르기에서 `drop-0156` 을 고른다.
2. 시각 입력칸에 `01:55:30` 을 넣는다.
3. 녹화를 시작하고 10배속으로 재생한다. 5분 하락이 30초에 지나간다.
4. 02:02 쯤에서 멈춘다.

말할 거리: 상위 20레벨이 100ms 마다 바뀌는 모습. 이 구간에도 갭이 없고, 모든 프레임이 depth20 과 같다(계획서 3절 대조).

## 6. 슬라이드·포스터용 정지 화면

| 무엇 | 어디서 |

| 갭 안내가 뜬 화면 | 장면 1 에서 갭 안에 멈춘 상태로 화면 캡처 |
| 급락 직전과 직후 호가창 | 장면 2 에서 01:56:19, 02:01:19 에 시각 입력칸으로 서서 캡처 |
| 모의 매매 누적 손익 곡선 | `runs/deeplob/depth20-seed0/paper_trading.png` (그림 글자는 영어, 서버에 한글 글꼴이 없다) |
| 결과 숫자 | 계획서 맨 위 72시간 판정, 3절 대조, 5절 메모 '결과' 와 '모의 매매 결과' |

## 7. 파일 두는 곳

영상과 캡처는 `pdf/`(git 밖, 발표 자료)에 둔다. 이름은 `showcase-gap-0732.mp4`, `showcase-drop-0156.mp4` 처럼 장면과 구간이 보이게 붙인다.

## 8. 확인

- 영상을 처음부터 끝까지 틀어 본다. 깜빡임이 없고, 숫자 띠가 잘리지 않고, 갭 안내가 읽혀야 한다.
- 다 찍으면 서버의 화면을 끄고(`Ctrl + C`) 노트북의 SSH 터널도 닫는다.
